## Load order (`web/index.html`)

Plain `<script>` tags, no modules and no build step, so everything works from `file://`. Order matters:

1. `data/static.js`, `data/league.js` (written by `league/export.py`): fill `window.LD.static` and `window.LD.league`. Per-hero, per-party and per-fight files (`data/hero/<id>.js` and so on) are loaded on demand by `App.load`.
2. `settings.js` (`Settings`, first: everything that moves or makes a sound reads it), `audio.js` (defines `Sound`; uses only WebAudio), `speech.js` (`Speech`), `town_music.js` (`TownMusic`; its own WebAudio context, reads the `al.sound` settings, needs nothing else), `art.js` (`Art`), `mount_art.js` (`MountArt`, right after `art.js`, which it needs at load), `daybook.js` (`Daybook`, also needs `art.js` at load), `paint.js` (`Paint`), `beasts.js` (`Beasts`), `monster_game_art.js` (`MonsterGameArt`, needs `Paint`), `anim.js` (`Anim`), `scenes.js` (`Scenes`), `town_scenes.js` (`TownScenes`), `wild_scenes.js` (adds to `TownScenes`, so right after it), `tavern.js` (`Tavern`), `camp.js` (`Night`, after `tavern.js`), `ballad.js` (`Ballad`, after `tavern.js`), `music.js` (`Music`; uses `Sound`, `Speech` and `LD` only when called), `isle.js` (`Isle`). These reference each other only inside functions (`Art` calls `Paint` and `Beasts` when drawing, `Scenes` calls `Isle` and `Anim`, `Night` calls `Tavern` and, when present, `Anim`), so the order among them is not load-critical, but all must load before `app.js`.
3. `app.js` (`App`; reads `LD`, builds lookup tables, registers nothing yet), `views.js` (registers the main routes with `App.route` and publishes `Views`, its shared helpers), the `views_<page>.js` route files (each registers one route and reads `Views`; `views_settings.js` also needs `Settings`, `Tavern` and `Speech`), `tarot_cards.js` (`TarotCards`, also used by the hero page's omens), `replay.js` (the replay routes and `#/fight/<id>`), `quiz.js` (`#/join`).
Not on the first load: the players for the replay pages load with their first page, in this order, through `App.need` (a `<script>` tag, so it works from `file://`): `battlefield.js`, `deaths.js`, `fight_fx.js`, `fight_director.js` (`#/fight`); `food_art.js`, `food_dishes.js`, `food_eat.js`, `meal_replay.js`, `meal_tavern.js` (`#/meal`); `tarot_replay.js` (`#/reading`, and the hero page for a reversed omen card); `music_replay.js`, `music_camp.js` (a music night); `night_replay.js`, `chess_replay.js` (other nights; chess also for the Yeti corner and the Frosthold board); `tables_replay.js` (`#/table`); `food_art.js`, `fish_art.js`, `fish_replay.js` (`#/catch`, and `fish_art.js` for the hero page's trophy wall and the Creel Book). `replay.js` lists them in `KIT`.
4. The inline `App.start()` runs the router, so every route must be registered before it.

Each file is one IIFE that publishes one global. Files only use globals defined above them, except `Sound`, which `app.js` and `replay.js` guard with `window.Sound`. `replay.js` also draws without `FightFX` or `skill_fx` (plain stand-in effects), so either can be missing.
